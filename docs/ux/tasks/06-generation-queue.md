# 06 · Очередь генерации на все билеты (P1)

## Зачем
Главное преимущество перед DeepSeek: не просить 40 раз, а нажать один раз. Нагрузка на сервер (2 CPU, 2 ГБ) и на модель ограничена, поэтому нужна очередь.

## Что сделать
- Вынести ядро генерации из `generate_ticket_answer` в функцию, которая не зависит от HTTP-соединения: собрать контекст → вызвать модель → сохранить ответ. SSE-эндпоинт для одиночной генерации использует её же.
- `POST /api/subjects/{slug}/tickets/generate-all` с параметрами `depth`, `wishes`, `only_missing=true`: ставит билеты в очередь (`exam_tickets.status` расширить значениями `queued`, `generating`, `error`; сохранить `error_text`).
- Фоновый обработчик берёт билеты по одному (параллелизм из переменной окружения `MAX_PARALLEL_GENERATION`, по умолчанию 1; пауза между запросами `GENERATION_DELAY_SEC`, по умолчанию 0). Очередь **переживает закрытие страницы**; при рестарте сервиса билеты `queued`/`generating` продолжаются.
- `GET /api/subjects/{slug}/tickets/queue` (или опрос списка билетов) отдаёт `{total, done, failed, running_ticket_id}`.
- `POST …/tickets/queue/cancel` останавливает очередь предмета; `POST …/tickets/{tid}/retry` повторяет ошибочный.
- Ограничение: одна активная очередь на пользователя; повторное нажатие показывает текущую.

## Интерфейс
- В шапке списка билетов кнопка «Подготовить ответы на все без ответа (23)».
- Во время работы: карточка с полосой «Готово 8 из 23 · можно закрыть страницу», кнопка «Остановить». Билеты в очереди помечены «в очереди», текущий — «пишу…».
- Ошибки: «Не удалось: 2. Повторить», с причиной по клику.
- Предупреждение при большом объёме: «Это займёт около N минут» (оценка по среднему времени одной генерации).

## Критерии приёмки
- Очередь из 40 билетов проходит до конца при закрытой вкладке; прогресс виден при возврате.
- Перезапуск сервиса в середине очереди не теряет билеты.
- Ошибка одного билета не останавливает остальные.
- Нагрузка: память не растёт линейно с числом билетов (проверить на 40 билетах).

## Открытый вопрос
Лимиты и стоимость модели Timeweb неизвестны. До запуска на реальных данных сделать пробную очередь из 5 билетов и показать владельцу время и расход.
