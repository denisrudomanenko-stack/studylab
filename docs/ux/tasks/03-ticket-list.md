# 03 · Список билетов: ввод, импорт из файла, правка, выбор (P0)

## Принцип
Ответы **не готовятся автоматически**. Список вопросов ведётся отдельно: вручную или загрузкой из файла. Тома видит весь список по предмету, правит его, отмечает пункты и **сама запускает** подготовку ответов по отмеченным (запуск — задачи 04 и 06). Добавление вопроса никогда не запускает генерацию.

## Что сделать

### Данные
- `ALTER TABLE exam_tickets ADD COLUMN position INTEGER DEFAULT 0` — порядковый номер в предмете (для старых — по порядку id); показывать его, а не `id`.
- Эндпоинты (дополнить существующие): `PUT …/tickets/{tid}` — менять `question` (уже есть, проверить), `POST …/tickets/reorder` (необязательно: список id в новом порядке), `POST …/tickets/bulk-delete` (список id).

### Ввод вручную
- Поле «Добавить вопрос» + кнопка «Вставить список» (многострочное поле, по одному вопросу на строку, как существующий `batch`).
- Предпросмотр до сохранения: «Найдено 38 вопросов», первые 3 строки, подсветка подозрительных (< 8 символов, дубликаты). Кнопка «Добавить 38 билетов».
- Разбор на сервере (`batch_create_tickets`): снимать «1.», «1)», «- », «Билет 1.», «Вопрос 1:», «№1»; склеивать многострочный вопрос, если следующая строка не начинается с номера; убирать дубликаты внутри списка и относительно существующих; вернуть `skipped`.

### Импорт из файла
- Кнопка «Загрузить файл со списком». Форматы: **TXT, DOCX, PDF, XLSX, JPG/PNG, фото с iPhone (HEIC)**.
- Эндпоинт `POST /api/subjects/{slug}/tickets/import` (multipart): возвращает **список вопросов для предпросмотра, ничего не сохраняя**; сохранение — тем же `batch` после подтверждения.
- Текстовые форматы: TXT/MD — как есть; DOCX — через `pandoc` (уже на сервере) или существующую конвертацию из `mklib`; PDF — `PyMuPDF` (текстовый слой); XLSX — взять колонку с вопросами (если колонок несколько, показать выбор колонки; для чтения нужна `openpyxl` — **новая зависимость, согласовать**).
- Изображения (JPG/PNG/фото): распознавание тем же механизмом, что `chat/ocr-image` (модель с vision). Перед отправкой уменьшать до ~2000 px по длинной стороне и применять EXIF-поворот. **HEIC:** Safari на iPhone при выборе файла обычно отдаёт JPEG; если приходит HEIC — конвертировать (потребует `pillow-heif`, **согласовать зависимость**) либо отвечать понятной ошибкой «Фото в формате HEIC не поддерживается, выберите другое». Решение согласовать с владельцем после проверки на реальном фото.
- Результат распознавания — **всегда** на предпросмотр и правку, не напрямую в базу: OCR ошибается.

### Список билетов (главный экран предмета)
Полный дизайн — в `ux-map.html`, экран 3.
- Шапка: «Выбрано 3 из 40», быстрые выборки «Все без ответа», «Снять выбор»; поиск по тексту; фильтры «Все · Без ответа · Готовы» (позже «Знаю · Ещё раз»).
- Строка: чекбокс · номер · вопрос (2 строки) · бейдж статуса («Нет ответа», «В очереди», «Пишу…», «Готов», «Ошибка») · действия «⋯» («Редактировать», «Обновить ответ», «Скачать HTML», «Удалить»).
- Редактирование формулировки на месте (двойной клик или «Редактировать»), сохранение по Enter/потере фокуса.
- Групповые действия над отмеченными: «Подготовить ответы (N)», «Удалить». Кнопка «Подготовить ответы» открывает мини-панель: глубина (Кратко/Стандарт/Подробно), пожелания, «Пропустить уже готовые» (по умолчанию включено) — см. задачи 04 и 06.
- Клик по строке открывает билет (задача 08); до неё допустимо текущее раскрытие ответа.
- Список по предмету, предметы сгруппированы по семестрам (задача 02): общего списка по всем предметам сразу не нужно.

## Критерии приёмки
- Вставка 40 строк с нумерацией разных видов даёт 40 билетов с правильными номерами; повторная вставка не создаёт дубликатов.
- Файл TXT/DOCX/PDF со списком даёт предпросмотр, который можно поправить; фото листа распознаётся с предпросмотром.
- Ни добавление, ни импорт, ни правка не запускают генерацию.
- Отметка 3 пунктов и «Подготовить ответы (3)» запускает генерацию ровно по ним.
- Поиск и фильтры без задержки на 150 билетах.
