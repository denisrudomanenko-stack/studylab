# 10 · Конвейер изображений: извлечение, описание, хранение, поиск (P0)

## Зачем
Иллюстрации из материалов (схемы, рисунки, формулы, микрофотографии) — востребованная часть ответов на билеты и работы ассистента. Нужен надёжный и экономный механизм, а не набор отдельных вставок.

**Прототип.** В PR #3 Код уже сделал первый вариант (распознавание картинок при индексации, `segments.json → images`, хвост «Иллюстрации из источников» в ответе). Этот вариант служит заготовкой, но его архитектуру нужно заменить на описанную ниже. Вынести прототип из PR #3 в ветку `feat/ux-10-image-pipeline` и переработать.

## Что сделать

### 1. Извлечение и фильтрация (при индексации источника)
- Брать картинки, которые уже извлекает `mk_convert(..., with_images=True)` (PDF через PyMuPDF, DOCX через pandoc).
- Отбрасывать мусор: меньше 8 КБ или меньше 120 px по короткой стороне; дубликаты по `sha1` внутри предмета; повторяющиеся на многих страницах (логотипы и колонтитулы: одна картинка чаще чем на 30% страниц).
- Нормализовать: максимум 1600 px по длинной стороне, JPEG (фото) или PNG (схемы с мелким текстом), EXIF-поворот. Использовать PyMuPDF (`fitz.Pixmap`), чтобы не добавлять зависимость. Если нужен Pillow, согласовать.
- Связь с текстом: определить номер сегмента (как сейчас по позиции в тексте), подпись («Рис. 3.2. …») из соседних строк, ближайший абзац (до 300 символов) как `context`.

### 2. Хранение (таблица, не `segments.json`)
```
images(id INTEGER PK, subject_slug, source_slug, segment INTEGER,
       path TEXT, sha1 TEXT, width INTEGER, height INTEGER,
       kind TEXT,          -- scheme | formula | table | photo | chart | other
       caption TEXT,       -- 1–2 предложения: что изображено
       latex TEXT,         -- только для kind=formula
       figure_label TEXT,  -- «Рис. 3.2», если найден
       context TEXT,
       status TEXT,        -- pending | described | skipped | error
       hidden INTEGER DEFAULT 0,
       created_at TEXT)
```
Миграция по шаблону `init_db`. Кэш по `sha1`: одинаковая картинка в двух источниках описывается один раз.

### 3. Описание моделью (vision), с контролем расхода
- Отдельный этап **после** «Прочитан»: текст источника доступен сразу, иллюстрации догружаются фоном со своим статусом «Иллюстрации: 12/80».
- Один запрос на картинку: тип, подпись-описание на русском, для формул — LaTeX, для декоративных — `SKIP` (запись `skipped`).
- Параллелизм 1, ограничение числа картинок на источник (по умолчанию 150, `MAX_IMAGES_PER_SOURCE`), повтор при сбое до 2 раз, ошибка одной картинки не останавливает остальные.
- В мастере и в загрузке: переключатель «Описывать иллюстрации» (по умолчанию включён) и оценка «≈ 80 иллюстраций, около 4 минут».
- **До боевого включения** сделать пробный прогон на одном реальном учебнике и показать владельцу число картинок, время и расход. Лимиты Timeweb неизвестны.

### 4. Поиск по иллюстрациям
- Для каждой описанной картинки создать чанк в векторном индексе предмета: текст `caption + figure_label + context`, `meta={type:'image', image_id}`. Тогда вопрос билета и вопрос в чате находят картинку по смыслу.
- `_rag_context` возвращает такие чанки отдельным списком `images` (не смешивать с текстовыми фрагментами, чтобы не расходовать `k`).

### 5. Отдача файлов
- `GET /api/images/{id}` (с проверкой авторизации и **защитой от выхода за пределы папки**; никаких путей от клиента). Кэш-заголовки, миниатюра `?w=400`.
- Существующий `media/{src}/{path}` оставить для читалки, но тоже проверить на path traversal.

### 6. Управление
- `PUT /api/images/{id}` — скрыть/показать (`hidden`), поправить `caption`. Скрытые не попадают в ответы.
- В читалке: у сегмента показываются его картинки (сейчас читалка выводит только текст; нужен рендер изображений, подпись, лайтбокс).

## Критерии приёмки
- На учебнике с 80 рисунками: мусор отфильтрован, остальное описано, прогресс виден, источник доступен для текста до окончания описания.
- Повторная загрузка того же файла не вызывает повторных запросов к модели (кэш).
- Запрос «строение клеточной стенки» находит соответствующую схему по описанию.
- Файлы отдаются только авторизованным; запрос с `../` не работает.
- Расход и время на тестовом учебнике приложены к PR.

## Вне объёма
Вставка картинок в ответы и чат, лайтбокс, панель иллюстраций, экспорт — задача 11. Разметка и обрезка картинок вручную — не нужна.
