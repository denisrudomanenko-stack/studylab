# 11 · Иллюстрации в ответах на билеты и в работе ассистента (P0)

## Зачем
Ответ на билет должен содержать нужные рисунки и схемы из материалов Томы. Ассистент должен уметь показать иллюстрацию и объяснить её. Всё управляемо: Тома может убрать, заменить и добавить.

Зависит от задачи 10 (таблица `images`, поиск, отдача файлов) и 04 (промпт).

## Что сделать

### Ответ на билет
1. **Кандидаты.** При генерации к фрагментам текста добавляется блок кандидатов (из `_rag_context(...).images`, топ по близости, лимит по глубине: Кратко 1, Стандарт 3, Подробно 5). Формат строки: `[img:ID | Рис. 3.2 | схема | «краткое описание»]`.
2. **Вставка моделью.** Модель сама ставит маркер `[img:ID]` в нужное место конспекта и **только** для предложенных ID. Правила в `prompts/ticket-answer.md`.
3. **Проверка.** Код после генерации проверяет маркеры: неизвестные ID удаляет, дубли убирает, лишние сверх лимита убирает. Формулы (`kind=formula` с `latex`) вставляются как LaTeX вместо картинки.
4. **Хранение.** В `exam_tickets.answer` лежит текст с маркерами `[img:ID]`, а **не** готовые URL и не хвост «Иллюстрации из источников». Рендер превращает маркер в `<figure>` с подписью «Рис. 3.2 · Лекция 4, §2» (ссылка на сегмент читалки).
5. **Ручное управление.** На экране билета панель «Иллюстрации»: миниатюры кандидатов и уже вставленных. Действия: «Вставить в ответ», «Убрать из ответа», «Заменить». Правка меняет маркеры в тексте ответа и сохраняется (с версией, если реализована задача 07).
6. **Нет подходящих картинок** — ответ без иллюстраций, без пустых заглушек.

### Лайтбокс
- Клик по картинке открывает увеличенную (`.modal.wide`), подпись, источник, кнопки: «Открыть в читалке», «Объяснить рисунок», «Скрыть из ответов» (меняет `hidden`).
- «Объяснить рисунок»: единичный запрос к vision-модели с **самой** картинкой и вопросом билета/чата; ответ показывается в лайтбоксе или в чате. Только по нажатию (расход).

### Ассистент (чат)
- В контексте ответа ассистента те же кандидаты и тот же маркер `[img:ID]`, лимит 2 на ответ. Подпись и ссылка на источник, как в билетах.
- Запросы вида «покажи рисунок про …» и «есть схема …» → поиск по иллюстрациям; ответ — найденные картинки с подписями.
- Фото, которые Тома прикладывает в чат, работают как сейчас (распознавание текста); в базу иллюстраций они **не** попадают.
- Подпись «Ищу по всем предметам» остаётся: картинки тоже из всех предметов; в ссылке указывать предмет.

### Экспорт и читалка
- Экспорт HTML (`/tickets/export`, `/tickets/{tid}/export`): картинки встраиваются как `data:` (JPEG до 1200 px), чтобы файл открывался офлайн; общий размер ограничить (предупреждение при превышении, например, 15 МБ).
- Читалка: рендер картинок сегмента (задача 10).
- `_md_to_html` и `md()` понимают маркер `[img:ID]` и markdown-картинки.

## UI-схема (экран билета)
```
Конспект ответа                 | Источники ответа
Клеточная стенка …              | Иллюстрации
┌ Рис. 3.2 · Лекция 4, §2 ┐     | [▨] [▨] [▨]  ← «Вставить»
│        [схема]           │    | Читалка …
└──────────────────────────┘
```

## Критерии приёмки
- Ответ на билет по теме со схемой содержит нужную схему в логичном месте с подписью и источником.
- Маркеры с несуществующими ID не попадают в ответ; число картинок не превышает лимит глубины.
- Тома убирает и добавляет иллюстрацию вручную; изменение сохраняется после перезагрузки.
- Лайтбокс работает на ноутбуке и планшете (жест «сжать», крупная кнопка закрытия).
- Экспорт открывается без интернета с картинками.
- Ассистент по запросу «покажи схему …» присылает картинку с подписью.

## Вне объёма
Редактирование самой картинки (обрезка, подпись поверх). Показ иллюстраций на телефоне допускается в чтении (задача 09); добавление и замена — нет.
