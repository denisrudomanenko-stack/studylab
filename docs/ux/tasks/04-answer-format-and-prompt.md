# 04 · Формат ответа и новый промпт (P0)

## Зачем
Главный результат продукта: конспект ответа на билет только из материалов Томы, нужной ей глубины, с источником у каждого тезиса и честным блоком «чего нет». Сегодня промпт разрешает «общие знания», объём один, поиск идёт по всем предметам.

## Что сделать

Генерация запускается только вручную: для одного билета с экрана билета или по отмеченным пунктам списка (простая версия — по одному подряд из интерфейса; фоновая очередь — задача 06). Уже готовые ответы при запуске по выбранным пунктам пропускаются; перегенерация — явная кнопка «Составить заново».

### Параметры генерации
- `GET …/tickets/{tid}/generate` принимает: `depth` (`short` | `standard` | `full`, по умолчанию `standard`), `wishes` (текст до 500 символов), `scope` (`subject` по умолчанию | `all`), `exclude` (список slug источников через запятую; используется в задаче 05).
- Сохранять в `exam_tickets`: `depth TEXT DEFAULT 'standard'`, `wishes TEXT DEFAULT ''` (миграция `ALTER TABLE`). В карточке предмета можно сохранить `answer_wishes` по умолчанию (`subjects.answer_wishes TEXT DEFAULT ''`): подставляется в новые билеты.
- Глубины (ориентиры для промпта и `max_tokens`):
  | depth | Смысл | Объём | max_tokens |
  |---|---|---|---|
  | short | тезисы, чтобы вспомнить за 30 секунд | 100–200 слов | 1200 |
  | standard | конспект ответа на 3–4 минуты | 350–600 слов | 2500 |
  | full | подробный разбор | 700–1100 слов | 4096 |

### Новый системный промпт
Готовый текст: [`../prompts/ticket-answer.md`](../prompts/ticket-answer.md). Заменить им `system_prompt` в `generate_ticket_answer`. Ключевые отличия от текущего:
1. Только материалы. Запрещено «Из общих знаний:». Вместо этого в конце обязательный блок `## Не найдено в материалах` со списком пунктов, которые обычно входят в такой ответ, но не нашлись во фрагментах. Если нашлось всё — блок пишется с текстом «Все ключевые пункты найдены в материалах».
2. Формат конспект: короткие тезисы, структура определение → основное содержание → формулы → значение/примеры.
3. Провенанс сохранить в прежнем формате `[src:SLUG#SEG | раздел: заголовок]`: от него зависят `md()` и `_md_to_html`.
4. Пожелания студентки учитываются, но не отменяют правила про источники.

### Поиск
- По умолчанию искать только в источниках **этого предмета**. Для этого добавить параметр в `_rag_context` (например `only_subject`), чат оставить как есть (по всем предметам, подпись «Ищу по всем предметам» уже в интерфейсе).
- `k=10` оставить; при `depth=full` можно `k=14`.

### Интерфейс (на экране билета)
- Сегментированный переключатель «Кратко · Стандарт · Подробно» над ответом. Переключение **не** перегенерирует автоматически: показывает кнопку «Составить заново (Подробно)».
- Свёрнутое поле «Пожелания к ответу» (placeholder: «Например: как у Иванова, с классификацией и схемой»).
- Кнопка «Составить ответ» / «Составить заново».
- Блок «Не найдено в материалах» стилизовать отдельно (приглушённая карточка с иконкой предупреждения); распознавать по заголовку `## Не найдено в материалах` в `md()`.
- Глубину и пожелания запоминать в билете (показывать последнюю использованную).

## Критерии приёмки
- Ответ **не содержит** фраз «Из общих знаний». Если в материалах чего-то нет, это перечислено в блоке.
- Каждый фактический тезис сопровождён `[src:…]`, который открывает читалку на нужном сегменте.
- Три глубины дают заметно разный объём в пределах таблицы.
- Поиск по билету не подмешивает фрагменты других предметов (проверить на двух предметах с пересекающимися темами).
- Экспорт HTML (`/tickets/export`) корректно отображает новый блок и чипы.
