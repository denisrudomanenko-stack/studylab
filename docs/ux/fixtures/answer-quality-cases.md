# Набор проверок качества ответа на билет (для приёмки задачи 04)

Назначение: ревью задачи 04 идёт по этому списку, а не по общему впечатлению. Код прогоняет набор на реальных материалах Томы (или на двух тестовых предметах с пересекающимися темами) и прикладывает к PR таблицу «случай → результат».

Материалы Томы мне неизвестны, поэтому случаи описаны по типу ситуации. Конкретные вопросы взяты из `tickets-messy.txt`, а недостающие подбираются по реально загруженным источникам: в таблице указано, какого рода билет нужен.

## Как прогонять
- Для каждого случая запустить генерацию по трём глубинам (`short`, `standard`, `full`), а случаи 1, 4 и 8 дополнительно с пожеланиями.
- Сохранить: текст ответа, число слов, список `[src:…]`, список `[img:…]`, время, число фрагментов в контексте.
- Режим `STUDYLAB_FAKE_LLM=1` проверяет только каркас (блок «Не найдено», разбор меток, лимиты). Качество текста смотрится на живой модели.

## Случаи
| № | Ситуация | Какой билет подобрать | Что должно быть |
|---|----------|----------------------|-----------------|
| 1 | Материалов много, тема раскрыта полностью | «Строение клетки прокариот» или любой билет, покрытый несколькими источниками | Структура: определение → содержание → формулы → значение. Каждый факт с `[src:…]`. Блок «Не найдено в материалах» есть и пишет «Все ключевые пункты найдены в материалах» (или честный короткий список). |
| 2 | Тема раскрыта частично | «Плазмиды: виды и функции», если в материалах только определение и один пример | Есть то, что нашлось, со ссылками. Недостающее (например, функции) перечислено в блоке «Не найдено». Модель не достраивает недостающее. |
| 3 | В материалах нет ничего по теме | Вопрос, которого нет в источниках, например «Транспорт веществ через мембрану» в предмете без такого раздела | Ответ: «В материалах по этому вопросу ничего не найдено» и блок «Не найдено» с общими пунктами. Никаких выдуманных тезисов, никаких `[src:…]`. |
| 4 | Материалы есть в другом предмете, но не в этом | Билет предмета A, тема лежит в предмете B | Ответ не использует фрагменты предмета B (поиск только по своему предмету). Блок «Не найдено» перечисляет пробелы. |
| 5 | Пересечение источников | Тема, которую по-разному излагают два источника | Расхождение отмечено нейтрально («по лекции… по учебнику…»), без выбора «правильной» версии от себя. |
| 6 | Латинские названия | «Грамположительные и грамотрицательные бактерии» | Латинские названия верные и курсивом; нет выдуманных видов, которых нет во фрагментах. |
| 7 | Формулы и таблицы | Билет, где есть формулы или сравнительная таблица (например, сравнение грамположительных и грамотрицательных стенок) | LaTeX `$…$` / `$$…$$` в формулах, таблица в markdown; рендер корректен в чате, на экране билета и в экспорте HTML. |
| 8 | Пожелания студентки | Любой билет с пожеланием «как у Иванова: с классификацией, без истории» | Пожелание учтено в структуре, но источники и блок «Не найдено» остаются. Пожелание «добавь из общих знаний» **не** снимает запрет и не меняет правила. |
| 9 | Дубль билета | «Строение клетки прокариот» (дважды в `tickets-messy.txt`) | Ответ на оба не противоречит; повторный запуск с `skip_done` не перегенерирует готовый. |
| 10 | Мусорный вопрос | «??» | Ответ не выдумывается: модель сообщает, что вопрос непонятен, или система не запускает генерацию. Падения и бесконечного ожидания нет. |
| 11 | Иллюстрации (после задачи 11) | Билет по теме, где в материалах есть схема | `[img:ID]` стоит только из списка кандидатов; число не больше лимита глубины (1/3/5); нет «хвоста» «Иллюстрации из источников». |
| 12 | Глубина | Один билет по трём глубинам | short ≈ 100–200 слов, standard ≈ 350–600, full ≈ 700–1100. Различие заметно. |

## Обязательные автоматические проверки на каждом ответе
1. Нет фраз «Из общих знаний», «как известно», «обычно считается» без ссылки.
2. Все `[src:SUBJECT/SLUG#SEG | …]` указывают на фрагменты, реально бывшие в контексте. Метка со «лишним» источником считается ошибкой.
3. Блок `## Не найдено в материалах` присутствует **всегда**.
4. Все `[img:ID]` есть в списке кандидатов, их число не превышает лимит.
5. Ответ не содержит вставок от модели вне формата (пересказ правил, «Конечно!», извинения).

## Что приложить к PR
- Таблица «случай × глубина → пройдено/нет», по случаям 1–4, 8, 10 и 12 обязательно.
- По одному полному примеру ответа каждой глубины (в приложении, не в описании).
- Строка про расхождения: какие случаи не прошли и почему.

## Что считается провалом (блокирует приём)
- Случай 3: ответ содержит тезисы без источников.
- Случай 4: в ответе фрагменты чужого предмета.
- Случай 8: пожелание отменило правило про источники.
- Отсутствует блок «Не найдено в материалах» хотя бы в одном ответе.
